## 应用运行时修补候选

仅将 Node 基础版本升至 24.22.3 的同发行版镜像，仍有 45 条高/严重记录。因此准备以下打包修补，尚待新提交的真实 CI 验收：

- 构建使用按摘要固定的 Node 24.22.3；生产依赖从构建结果裁剪，开发依赖不进入运行时。
- 运行时使用按摘要固定的 Google Distroless Node 24 / Debian 13 非 root 镜像，移除运行时 npm、shell 和多余系统工具。该候选基础镜像已实际扫描，零高/严重；这不等于最终应用镜像或其中 Node 二进制的运行版本已验收。
- 保留 UID/GID `10001:10001`、`/data` 挂载、`/data/store` 数据及 `/data/store.mfa-key` 默认位置；保留 Compose 的只读根、权限、网络、端口和资源限制。不对已有卷做 chown、清库或重建。
- 通过 `server/runtime.ts` 先完成现有初始化，再加载服务；使用镜像内 Node 作为入口。维护命令继续使用 `docker compose exec app node ...`；镜像不再提供 `sh` 或 `npm` 交互命令。
- CI 中复用 `verify-container.ps1`，实际运行隔离容器，检查严格 HTTPS/WSS、权限、账号/文件/配额/交付、MFA、重启与备份恢复；随后扫描同一 `safedrop:verify` 镜像。仅将脱敏汇总放入 `reports/ci`，不发布生成的账号、私钥或备份。
- 容器 MFA 探针核对实际 Node 24 至少为 24.22.3，并把版本记入结果；旧容器报告缺少该证明时，新的 CI 运行时汇总不会沿用旧成功。

本地已用官方校验和验证的便携 Node 24.22.3 完成构建、27/27 测试、编译后入口初始化/严格 HTTPS/重启账号保留和五组 MFA 探针；没有修改系统 Node 安装。前端仍为 `index-7EgnN7Bg.js`。这些是宿主机证据，不标为新镜像已通过。第一次入口辅助检查误用了数据库文件名，修正辅助脚本后复验成功；产品数据库文件和路径没有更改。

此候选需要手动推送后取得新 CI 结果。新镜像通过隔离运行与扫描后，再由使用者安排保留现有卷的实际升级，核对旧记录、账号及 CA；目前运行容器仍为此前已验收版本。没有提前部署候选。

## 网关剩余风险

| 发现项 | 上游范围与当前处置 |
| --- | --- |
| CVE-2026-78661，`golang.org/x/net v0.60.0` | HTML 解析拒绝服务，上游 `v0.62.0` 有修复。当前 Caddy Release 的依赖仍为旧版，需结合网关构建及功能验证处理，不能仅修改扫描报告 |
| CVE-2026-116587，`github.com/go-jose/go-jose/v3 v3.0.5` | 不可信 RSA JWK 解析拒绝服务；上游修复在 v4，v3 没有对应修复版。Caddy 的 Smallstep 依赖仍经旧 crypto 包使用 v3 |

在忽略提交的专用目录试验了精简网关模块和上游依赖升级。`go.step.sm/crypto v0.92.0` 已切换至 go-jose v4，但与当前 Smallstep certificates v0.30.2 有 JWT API 编译不兼容，试验未通过，未应用到网关、未提交试验源码，也未自行修改密码学代码。

当前本地网关仅配置内部证书和反向代理，没有配置接收用户 JWK 或 HTML 模板解析；这用于评估暴露面，不能单凭配置就断言组件完全不受影响。网关镜像保留原版本，风险检查继续失败。兼容的上游修复、必要的独立网关构建或有证据支持的适用性判定仍待处理；不添加通配例外、不使用 `--ignore-unfixed`、不把未验证假设写成通过。
