| 文件完整性 | 上传与下载的 SHA-256 一致 | 通过 |
| 长连接 | 多次业务与文件操作复用同一 WSS 连接 | 通过 |
| 重启恢复 | 已完成文件、部分上传确认偏移、账号资料及 CA 在重启后保留 | 通过 |
| 续传完整性 | 重启后从持久化偏移续传，最终文件 SHA-256 一致 | 通过 |
| 审计连续性 | 重启后的审计链匹配重启前独立保存的检查点 | 通过 |

原始报告按配置检查、重启前、重启后三个阶段记录，分别有 8、5、6 个检查组；阶段之间有重复检查，不能将其视作 19 个互不重复的安全用例。

日志末尾的 `health: starting` 出现在容器刚重启后、Docker 的下一次周期检查之前。报告成功建立重启后的 HTTPS/WSS 连接并完成传输及恢复断言，不依赖这一瞬时显示判定业务可用。

## 验证范围

这次结果证明上述容器及协议场景通过，不代替浏览器的文件选择、磁盘保存授权、公钥设备保存与实际界面操作。浏览器后续操作见 [浏览器验收清单](浏览器验收清单.md)。

公网域名与 Let's Encrypt 证书签发、磁盘满与写入错误、长时间运行及全局日志增长控制仍需单独验证。应用层限流测试也不能证明能够抵御任意规模 DDoS。
