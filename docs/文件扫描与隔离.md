# SafeDrop 文件扫描与隔离

2026-11-19，第 3 阶段（03/09 增强）候选开发中。本机真实引擎、受控状态套件、编译版及新增 Edge 界面已验证，最终 Linux 镜像、真实 CI 与本机原卷升级仍待执行。此前备份加密 `66c22eb` 及收尾 `6f78f7f` 已验收；当前运行容器保持该版本，不将本机结果写成容器已通过。

## 范围与状态

服务端强制检查文件扫描结果。上传先完成大小、SHA-256、持久化和配额转换，再登记等待扫描；上传完成不代表可供下载。旧文件没有扫描记录时显示“未扫描”，升级不把旧数据默认为安全，不删除原文件或授权。SQLite 增量迁移至版本 6，只新增 `file_scans` 表与队列索引。

状态为未扫描、等待扫描、正在扫描、扫描通过、威胁隔离和扫描未完成。记录绑定文件标识、大小、SHA-256、请求代次、引擎/签名库版本和检查时间。新上传自动排队；所有者可请求旧文件扫描或重试，管理员不能代替其他用户放行、读取或删除文件。扫描结果默认有效 168 小时，过期或异常未来时间需重扫，防止一次通过无限期使用；配置上限 30 天且不能关闭检查。

“隔离”为服务端逻辑隔离：对象留在原私有路径，所有者下载、接收授权下载/续传及发送准备/创建均被阻止，已保存到客户端的字节无法收回。不提供忽略结果或人工强制放行；只有重新扫描通过才能重新访问。原交付授权保留，恢复通过后仍须满足原授权。隔离、失败及等待均继续计入所有者和全局存储，所有者可按原永久删除流程处理。

读取入口在初始化、续传、每块、带宽等待后、读入后及发送前重查扫描和授权；重新请求扫描会先使原通过状态失效，并取消等待中的下载。扫描器与删除共用对象锁；备份暂停新扫描并等待在途扫描收尾，保留所有扫描状态和原审计。进程重启将中断任务重新排队，不改成通过。审计预算或事务失败不能发布通过结果。

## 引擎与部署设计

采用官方 ClamAV **1.5.5**。该安全修补于 2026-11-18 发布；调研时官方 Docker Hub 仍以 1.5.4 为稳定镜像，故从固定 SHA-256 的官方 1.5.5 发布包构建独立扫描器，保留修补来源与最终版本检查，不自行修改 ClamAV 密码学或扫描实现。当前发布包仅接入 Linux amd64，其他架构会拒绝构建。

Linux x86_64 包摘要 `fff17fb1f8917d1ea1308c9736dabe376077458aba000a5dadcce7193a8c538c`；本机验证的 Windows x64 包摘要 `90169f5e551010bfbd0208b50d9b2fa8988ef396cccbd46b0cc8cae03e22a4a4`。运行镜像只包含 ClamD、FreshClam、依赖动态库和证书，固定非 root distroless Node 基底。上游许可证与源代码链接保存在 `deploy/scanner/LICENSES.txt`。包版本元数据保留用于镜像清单，不声称安装了完整 deb 的工具和文档；未复制旧引擎。固定官方 1.5.4 镜像只提供签名数据种子，启动先尝试官方更新，随后每 6 小时检查更新；断网缓存仍须满足每次扫描的时效要求。新旧签名文件不覆盖已有数据库。

应用使用 ClamD `INSTREAM`，只传文件字节，不发送业务路径或给扫描器挂载业务/备份/密钥目录。扫描 TCP 无认证及加密，须限制在部署隔离内网且不发布端口；外部用户通道仍为原 HTTPS/WSS。签名更新仅从 ClamAV 官方服务下载数据库，不向公共多引擎平台提交文件。扫描器独立非 root、只读根、禁止提权、丢弃 capabilities，有界 CPU/PID/内存和临时空间，签名库使用独立持久卷。暂按官方建议预留约 4 GiB 内存，实际启动、更新、容量和最终镜像仍需验证。

ClamD 客户端使用 NUL 命令终止、4 字节大端分块长度及零长度结束，单连接有绝对超时、响应长度上限和背压。发送时计算真实内容摘要并检查文件状态，拒绝错内容、额外/畸形/提前响应；只接受严格的 `stream: OK` 为通过。扫描前后核对引擎/签名库版本，要求至少修补版本、签名不超过 72 小时且时钟无异常；扫描期间版本变化需重试。引擎不可用、超时、数据库过期、扫描超限或加密内容均不判通过。

配置单个扫描工作线程、流入最大 512 MiB、展开总量 1 GiB、递归 16 层、最多 10000 文件及 60 秒引擎扫描上限；开启 `AlertExceedsMax` 和加密内容检测。限制或加密内容告警记为无法完整扫描；真实威胁记为隔离。完整检查不保证发现所有恶意内容，签名及引擎需持续维护；已经通过的文件仍应谨慎打开。镜像漏洞检查不能穷尽上游静态捆绑组件，也不能替代文件内容检测。

## 配置与维护

| 环境变量 | 默认值 | 约束 |
| --- | --- | --- |
| `CLAMD_HOST` | 未设置 | 可信扫描器地址；未配置时也不允许下载或交付未通过文件 |
| `CLAMD_PORT` | 3310 | 1～65535；Compose 使用服务名 scanner 且不发布端口 |
| `SCAN_TIMEOUT_MS` | 90000 | 每个 TCP 交换绝对超时，100～300000 毫秒 |
| `SCAN_MAX_BYTES` | 536870912 | 正整数且不能大于 512 MiB；不改变账号/全局预算 |
| `SCAN_DATABASE_MAX_HOURS` | 72 | 正数、最多 168 小时；超期或异常未来签名拒绝检查 |
| `SCAN_RESULT_MAX_HOURS` | 168 | 正数、最多 720 小时；不能关闭结果到期检查 |

Compose 额外需要扫描器 4 GiB 内存、最大 1536 MiB 临时空间和独立 `scanner_data` 持久卷；首次下载约百 MiB 的引擎/签名并加载数据库会增加构建启动时间，容器等待上限为 600 秒，CI 镜像作业上限 45 分钟。预留宿主机资源后再升级，不能删除旧业务卷来解决启动失败。扫描器不健康时可检查其日志与官方更新连接；恢复服务后由所有者重试失败项，已失败项不会无上限自动重试。处理中断的扫描在应用重启时重新排队；后台审计预算不足等待 30 秒重试，结果/审计提交失败保持阻止状态，重启后重新检查。

本机直接运行也必须提供独立且使用 UTC 的 ClamD 及相同限制/告警策略，例如将 `CLAMD_HOST` 指向受保护的本机回环服务；不要将 TCP 暴露公网。接口没有忽略扫描或管理员代放行功能。升级后旧文件保留但需所有者首次请求扫描，通过后才恢复下载/交付；旧备份可正常验证和隔离恢复，恢复出的旧文件同样默认未扫描。当前机制未提供内容净化、沙箱执行、DLP 或端到端加密。

已有升级数据卷不适合直接换回只支持 SQLite 5 的旧程序。若确需回退，保留升级卷，在全新目录恢复升级前备份并匹配原版本及独立部署密钥，先隔离核对，不覆盖当前数据或降低扫描状态。

## 验证与尚待事项

原回归夹具显式使用仅限测试的受控通过引擎，并等待扫描状态；不将这些模拟结果作为真实威胁检测证据。新增测试必须覆盖真实 TCP 协议、错误/超时/版本/签名时效、旧文件拒绝、各读取与交付路径、重新扫描和过期、竞争/重启、配额/删除、审计及加密备份恢复。真实引擎应另使用官方签名库和安全测试样本验证，不以模拟通过代替。

两个官方发布包均已完整下载并校验，Windows 便携引擎和官方签名库已实际运行，未修改系统防病毒设置。真实 1.5.5/28187 检出客户端内存构造的 EICAR 及 ZIP 内测试样本，实际通过无害/空文件并拒绝加密无害 ZIP、递归超限 ZIP；守护进程可能使用自己的私有临时文件。编译版在 Windows 对旧文件、真实断连、到期、授权、加密备份和重启也通过，但恶意样本写盘/API 隔离只安排在 Linux 容器临时目录，Windows 编译探针明确 `malwareApi:false`，CI 门禁拒绝将其当作最终容器报告。

Edge 在 `http://localhost:1603` 临时夹具直接观察 B41～B45，隔离提示使用明确标注的受控无害状态行，不能作为真实威胁识别证据。截图与结果见浏览器清单和验证记录。最终 CI 需实际构建/运行三个镜像，用真实引擎在 `/tmp` 临时账号执行 EICAR/API 拒绝、配额、旧文件、到期、重启及加密恢复，然后扫描三个实际镜像且高/严重均为零；之后使用者执行版本 10 本机原卷验收。上述 Linux 和原卷结果尚未取得，阶段仍未标记完成。Docker 工具此前受权限限制，保留该边界，不绕过权限或证书，也不重建已有数据卷。
