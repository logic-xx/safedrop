# SafeDrop 实操录屏逐句稿

主线建议录成 **6～7 分钟**。讲义要求看到编译、部署和测试的实际过程，文件交互优先录真实画面。安装、构建、扫描或测试的等待段可以剪短，保留实际命令、开始动作与最后结果。分钟数用于排练。

## 开拍前摆好窗口

- **终端 A**：打开独立解包的录屏源码目录，负责安装、构建和启动。终端 B 同样进入这个目录，负责验证报告和摘要比对。
- **Edge 窗口 A 和 B**：用两个独立浏览器配置，分别登录临时发送方与接收方。本机新初始化的录屏环境可以用 alice 发送、bob 接收，临时 admin 留给维护操作。临时账号和本机 CA 提前准备。登录、口令输入、文件授权弹窗中的个人路径，以及任何私钥、邀请或恢复码都在镜头外处理。
- **录屏舞台**：只录浏览器和专用终端，先做 10 秒试录确认声音和字能看清。正常传输用可信 HTTPS 及已连接的真实 ClamAV。后面的回环 HTTP 夹具画面加字幕「本地界面夹具」。
- **样本**：从 `output/phase5/recording/samples` 取得 `demo-a.bin`（24 MiB）与 `demo-b.bin`（16 MiB）。另有 demo-ready.bin（20 MiB）。三个文件都是零填充的无害演示件。先在镜头外用发送方上传 demo-ready.bin，等它扫描通过，作为并发镜头中要下载的文件。

**留住**　`npm run build` 命令、Vite 成功输出、实际入口打开三幅画面。

## 02 启动与安全场景 00:55–01:40

**画面**　用已经排练过的专用环境。Windows 直接运行路线在独立源码目录按顺序执行 `npm run setup`、`npm start`，打开实际配置的可信 HTTPS 入口。若使用专用 Compose 演示环境，则录该环境的实际启动命令及健康、就绪状态。终端 B 实际运行 `npm run security:report`，留结尾汇总。若本次仍在运行，可在后面回切同一终端拍结果。

若要隔离现有 `8443` 服务，在**全新录屏源码目录**先完成下面的本机配置。需要已有可用的回环 ClamAV，端口使用其实际监听值。例子中的 3429 是现有扫描夹具的默认端口。首次启动前核对并信任本次临时 CA 的公开证书。

~~~powershell
$env:LOCAL_DIR = '.local/recording'
$env:DATA_DIR = '.local/recording/data'
$env:TLS_CERT = '.local/recording/tls/server.crt'
$env:TLS_KEY = '.local/recording/tls/server.key'
$env:PORT = '18444'
$env:APP_ORIGIN = 'https://localhost:18444'
$env:CLAMD_HOST = '127.0.0.1'
$env:CLAMD_PORT = '3429'
npm run setup
npm start
~~~

**照读**

> 现在打开的是专用演示环境的 HTTPS 入口。浏览器通过可信 CA 验证 localhost 的服务器证书。第二个终端正在跑独立的自动安全场景，后面我会对照界面操作和测试输出。

**留住**　启动成功、浏览器实际 HTTPS 地址和测试汇总。通过数按当次输出念。引用历史 CI 时加「最终验收基线的 Linux CI」字幕。

## 03 并发、暂停和续传 01:40–02:50

**画面**

1. 在发送方的「文件工作台」点「选择文件」，一次选择 `demo-a.bin` 和 `demo-b.bin`。
2. 两个上传进行中时，在同一账号对预先扫描通过的 demo-ready.bin 点「下载 / 续传」。滚到「传输队列」，录到上传和下载进度交错增长。
3. 在 `demo-a.bin` 的上传行点「暂停」，等状态显示「已暂停」。用鼠标指着非零进度，再点「继续」，留进度从原位置推进的画面。若专门演示刷新后的续传，暂停后刷新，镜头外重新登录，再选同一个 `demo-a.bin`。
4. 等到 `demo-a.bin` 显示「已完成」，工作台对应行显示「扫描通过」。可以剪掉等待的中间几秒。

**照读**

> 现在这里有两个上传任务和一个下载任务，都在推进。我把第一个上传暂停，当前已经确认了屏幕上的这个位置。点继续以后，它沿着原来的进度往后传。文件上传结束后还要做完整性校验和扫描，通过后的文件才开放给下载和交付。

只拍到同一页面内的暂停和继续时，说「暂停和继续」。若确实拍到了刷新、重登和重新选择文件，再说「刷新后重新认证，沿用服务端确认的位置」。

**加拍 15 秒公钥登录**　提前在临时普通账号的「安全中心」完成「绑定本机公钥」，绑定时不录口令。在镜头中退出、用同一个浏览器配置点击「使用本机公钥登录」，拍到返回工作台。可以念「服务器验证一次性挑战的签名。用来签名的私钥保存在本机浏览器里。」

## 04 指定接收方、下载和比对摘要 02:50–04:00

**画面**

1. 发送方在 `demo-a.bin` 那一行点「发送给用户」，填临时接收账号与有效期。点击「核对接收账号」，勾选「我已核对接收账号」，再点「确认发送」。留住成功提示与到期时间。
2. 切到接收方窗口，进入「收发文件」，点「刷新收发记录」，找到「收到的文件」里的 `demo-a.bin`。点「下载 / 续传」，保存成 `received-demo-a.bin`。下载时可选拍一次「暂停」和「恢复下载」。回到传输队列观察完成。
3. 在终端 B 把下面两条命令中的文件路径替换成实际的源件和保存件。画面停在两个相同的哈希值。可以将两个文件放在一个脱敏的演示目录内，让路径也适合录屏。
4. 若准备了第三个独立临时账号，切过去打开「收发文件」，拍到「当前没有接收记录」。服务端越权拒绝另拍自动测试的实际 PASS 行。

~~~powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '.\demo-a.bin'
Get-FileHash -Algorithm SHA256 -LiteralPath '.\received-demo-a.bin'
~~~

**照读**

> 我把这个文件的读取权限交给指定账号，原文件仍属于发送者。接收方在这里能看到并下载。现在本地原件和下载件的 SHA-256 完全一致，这是文件完整性的一条直接证据。这个没拿到授权的账号在收件箱里看不到文件。服务端收到不具备授权的读取请求时会拒绝，旁边是对应的协议测试结果。

### 镜头外准备夹具

- **扫描**：`npx --no-install tsx tests/scans-browser-fixture.ts`，默认回环 1603。需要真实 ClamAV。夹具可通过 `CLAMD_REAL_HOST` 和 `CLAMD_REAL_PORT` 指向回环服务，默认 127.0.0.1:3429。受控隔离行已预置，无需制作或上传恶意样本。
- **到期**：`npx --no-install tsx tests/delivery-expiry-browser-fixture.ts`，默认回环 1604，同样需要真实 ClamAV。登录临时接收方 `expiry-reader`，先录有效授权，再在**本次终端输出的新夹具根目录**创建名为 `simulate-expiry` 的空文件。该标记只推进该夹具的交付时钟两小时。结束后可移走自己刚创建的标记。
- **加密备份**：`npx --no-install tsx tests/backup-browser-fixture.ts`，默认回环 1602。它生成独立账号和无害样本，并预置旧明文副本。首次用本机 `maintenance keys-init` 为**该夹具**初始化独立备份密钥，参数从本次 `fixture.json` 的 `root`、`backups`、`keyFile` 字段取得。维护页应显示「新备份加密已就绪」。创建备份前保存独立检查点，再在离线终端执行 `verify` 和 `restore`。命令参数与目标目录见[存储维护与恢复](存储维护与恢复.md)和[备份加密与密钥管理](备份加密与密钥管理.md)。
- **保留依据**：脱敏证据包里有 `scan-fixture.png`、`expiry-fixture.png`、`encrypted-backup-fixture.png` 和 `local.json`。用历史素材辅助讲解时注明来源。只录到校验时，旁白只说「校验成功」；只展示已归档的恢复结果时，明确说「这是本机隔离恢复的验收记录」。
