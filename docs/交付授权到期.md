# SafeDrop 交付授权到期

2026-11-19，第 4 阶段（09 增强）已按范围完成，实现为 37b81ef。本机构建、54 项检查、176 个 TLS/WSS 场景、Windows 编译版真实引擎探针和 IAB B46～B50 通过；真实四个 CI 作业、版本 11 Linux 期限/恢复与三镜像门槛通过。本机版本 11 原卷升级保留 968 条原记录及账号、CA、独立备份密钥，实际 HTTPS/WSS、加密恢复和 Edge 期限/旧授权标签补核通过。中等级镜像发现仍为独立未解决事项；各轮结果及限制见[验证记录](验证记录.md)。

## 期限与兼容

新授权由发送者选择 **1～720 的整数小时**，默认 **168 小时（7 天）**。`deliveries.prepare/create` 接受可选 `hours`，服务端验证类型和范围，再根据创建时的服务器时间计算绝对毫秒 `expires`；客户端提交的创建/到期时间不作为授权依据。省略 hours 的旧客户端也会取得默认有限期，显式 null、零、负数、小数、字符串和超范围均拒绝。

SQLite 增量迁移至 **7**：在 deliveries 增加非空 expires 列、默认 0 及到期查询索引，保留原身份、文件、撤销和审计。旧授权的 **0 表示历史未设置期限**，不能通过新创建接口请求无期限授权。旧授权不被批量改期、撤销或删除；界面明确标注“旧授权 · 未设置到期时间”。

重复或并发发送同一文件给同一接收者，若已有有效授权，返回原标识和原期限，不延长时间或改变历史无期限授权。需要改变有效期时，由所有者先撤销再重新发送。过期后重发创建新标识和新期限，旧标识永不借新授权恢复。

## 服务端拒绝与状态

当前服务器时间 **大于或等于** expires 即到期。所有者原有文件权限不受交付期限影响，接收者的下载初始化、前缀续传、分块和扫描详情均检查精确的授权与期限；带宽等待后、实际读入后以及编码完响应、发送前再检查。客户端时间和按钮状态不能代替服务端判定。

每个在途接收下载有独立期限定时器，取消带宽等待及可取消的摘要计算；取消和异步返回后仍须重新检查。长延时按 Node 定时器上限分段，避免三十天授权被截为一毫秒定时器。事件循环或系统时钟会影响定时器唤醒，最终读取/发送检查始终依据当前服务端绝对时间；部署维护者需保持主机时间可信。

后台每秒最多处理 **16** 个已到期授权，以事务保存 `revoked=1`、`reason=expired`、`revokedAt=原期限` 和 `deliveries.expire` 审计，再中止相关在途下载。审计容量预留不足时等待，事务失败则回滚；访问检查和独立下载期限不依赖后台成功，不能因此继续放行。完成的到期状态不会因重启或时钟回退恢复。

创建时也会在同一事务内结束该文件/接收者已有的过期授权，再创建新授权。有效授权数量预算不计算过期记录；原表历史与审计继续保留。手动撤销、文件删除及账号停用沿用原流程，已先到期的授权保留到期原因。

## 界面、事件及恢复

发送确认页显示整数小时选择与期限说明。成功反馈显示服务端返回的实际到期时间，重复发送说明没有延长期限。收发列表显示期限；到期显示“已到期”并禁用下载/续传，旧授权显示历史无期限标签。收到的过期记录保留供核对，手动撤销、源文件删除或账号停用仍按原规则移出接收列表。

列表返回 `now` 和每行 `expires/expired`；页面以服务器观测时间加浏览器单调经过时间更新展示，刷新时重新同步。显示最多有轮询/渲染延迟，不构成权限保证。服务端拒绝 `DELIVERY_EXPIRED` 后，传输任务显示到期终态并解除旧续传关联，不删除已经保存的文件内容。

`deliveries.create/download/revoke` 继续记录身份，并附期限；`deliveries.expire` 由服务端生成参与者字段，普通账号只看到自己参与的到期事件，无关账号不可见。到期不代表接收方已读或已完整保存。

一致备份直接保存新列和所有到期/撤销状态，加密、独立检查点与全新目录恢复规则不变。恢复不会重新从恢复时刻计算期限；已过期授权仍拒绝，历史无期限授权仍按原授权及扫描规则处理。原卷指纹覆盖完整授权身份和期限，仅容许有限期授权的预期自动到期状态变化；专门探针另验证终态和旧标识不能复活。

## 验证边界

`tests/deliveries-suite.ts` 新增 16 个真实 TLS/WSS 场景：范围/默认、重复与并发、精确边界、下载中与真实带宽等待中到期、等待后/读取后/前缀摘要中/响应前复核、重发、事件隔离、审计回滚、重启、加密恢复和版本 6 增量迁移。文件扫描在这些协议回归中使用显式测试引擎，不能视为新的实际恶意内容识别证据。

`tests/container-delivery-expiry.mjs` 对编译入口使用真实 ClamAV 和全新临时账号，检查实际无害文件、独立期限取消、重发、旧授权、重启、事件及加密恢复。Windows 编译结果为 `platform=win32`，不充作 Linux 容器证明；随后 37b81ef 的真实 CI 已取得 platform=linux、SQLite 7、七组期限/恢复与原数据隔离证明，通过版本 11 门槛。随后使用者在普通 PowerShell 完成同一版本 11 原卷升级；工具读取新报告，并在严格 TLS 下核对实际入口及已复制的加密恢复副本。PowerShell 5.1 的静态 CheckOnly 也通过；工具没有访问本机 Docker 引擎。

`tests/delivery-expiry-browser-fixture.ts` 为新界面准备独立回环夹具，可用 BROWSER_EXPIRY_ROOT 恢复已有目录。三份无害文件由实际引擎检查，专用 `simulate-expiry` 标记只将该夹具的交付判定时间前移两小时，不修改系统时钟、扫描时间或原部署；完成后须移除。首轮 Edge 扩展未连接，B46～B50 由内置浏览器直接完成，报告明确浏览器类型并区分界面、时钟模拟和只读/API 补核；后续通过 Edge 扩展恢复同一夹具登录页；又在实际 https://localhost:18443 以验证部署的 bob 登录，观察新有限期、旧无期限及未扫描阻止下载标签，点击退出后确认登录页。Edge 未重复 B46～B50 完整交互或触发文件下载。原夹具三个文件共 192 B 未改，模拟已解除；IAB 最后通过刷新回到登录页。

本版不提供原地延长、任意日历时刻、接收次数限制、匿名链接、通知或自动删除历史。不能收回已发出或保存的字节，也不提供可靠外部时间源或多进程协调。数据库 7 卷不直接交给只支持版本 6 的程序；需要回退时，保留当前卷并将升级前备份恢复到全新隔离目录，匹配原版本与独立密钥，不覆盖当前数据。
