## 1. 配置与资源预算

生产入口通过环境变量配置，字节数采用整数，GiB/MiB 按 1024 换算。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `GLOBAL_STORAGE_BYTES` | 10737418240（10 GiB） | 全部账号已完成文件和完整上传预留之和的上限 |
| `GLOBAL_OBJECT_LIMIT` | 10000 | 全部已完成文件和未完成上传的数量上限，防止零字节对象绕过字节预算 |
| `MIN_FREE_BYTES` | 268435456（256 MiB） | 为数据库、审计、系统余量等保留的物理磁盘空间 |
| `AUDIT_LIMIT_BYTES` | 67108864（64 MiB） | 审计事件 UTF-8 字节加每行 128 字节估算开销的逻辑上限 |
| `UPLOAD_TTL_HOURS` | 168（7 天） | 未完成上传距最后活动的过期时间 |
| `CLEANUP_INTERVAL_SECONDS` | 0 | 后台清理间隔；0 表示关闭，管理员仍可手动预览和清理 |
| `BACKUP_DIR` | `DATA_DIR` 加 `.backups` | 私有备份目录，必须与业务数据目录互不包含 |
| `BACKUP_KEY_FILE` | `DATA_DIR` 加 `.backup-keys` | 独立备份密钥文件，须在业务及备份目录外；启动不自动创建 |
| `BACKUP_LIMIT_BYTES` | 21474836480（20 GiB） | 所有备份及未完成副本的总字节预算 |
| `BACKUP_MAX_COUNT` | 3 | 备份及未完成副本的份数上限；独立容器验收配置为 10 |

全局 `used` 为所有文件大小之和，`reserved` 为所有未完成上传的完整声明大小之和，包含清理待重试占用；交付授权不重复计费。新任务在第一个异步磁盘操作前核对预算并写入预留，同一进程的不同账号/连接不能同时突破余额。已有占用超过新配置时保留数据，拒绝新的超额分配。另有全局对象数量上限，跨账号的零字节文件及任务也计数。

物理余量使用数据文件系统对当前进程可用的 `bavail × bsize`。尚需写入的预留为 `sum(max(0,size-offset))`；新任务要求余量覆盖最低保留、全部未写预留和本次完整大小。分块在带宽等待后再次测量，检查失败或不足时拒绝写入，保留任务、原确认偏移和预留。外部进程仍可能消耗磁盘，检查不能代替实际 I/O 错误处理和部署监控。

审计在操作开始前预留有界记录预算，达到阈值时限制新增操作；部分认证和备份使用较小预算。硬上限附近停止追加拒绝日志，防止流量放大存储，因此不能声明每次拒绝均独立落盘。登录、公钥及会话变更与对应审计在事务内提交；审计失败时回滚。历史链不自动删除、截断或重建。

审计预算不是 SQLite、WAL 或全文件系统的物理大小上限；备份另有预算。管理员应在接近阈值前保存独立检查点及完整归档、检查磁盘，再由维护者审核调整容量。首版不提供在线审计裁剪或自动删除旧备份。

## 2. 管理员维护界面

管理员进入“存储与维护”。普通用户没有入口，服务端对全局状态、清理和备份分别鉴权。页面只返回汇总值及备份编号、时间、大小、加密状态和公开密钥编号，不提供其他用户文件列表、密钥或备份内容下载。没有可用密钥时禁用新备份并提示部署维护者处理，文件服务继续可用。

过期预览每批最多 16 个候选。输入“清理过期上传”后，逐项重新检查活动时间和任务锁，跳过正在初始化、写入、完成或已恢复的任务。正常恢复请求和成功分块刷新活动时间，重启保留；旧任务无活动行时回退到原创建时间，迁移不改写旧时间。后台清理默认关闭，升级不会立即自动清除已有任务。

清理只处理未完成上传，同时检查暂存及发布崩溃遗留对象。沿用持久化删除意图、物理清理确认后释放占用的规则；失败保留原行和完整预留，可恢复存储后重试。未知孤立对象不自动删除。过期清理会永久移除对应未完成数据，启用后台策略前应确认保留期限和用户约定。

备份时暂时拒绝新业务，允许心跳、基本信息和维护状态；等待已接受操作收尾后复制，完成或失败均解除维护状态。收到 `MAINTENANCE_BUSY` 的传输可以稍后重试，不能将其当作文件丢失。

## 3. 备份内容与边界

默认本机目录为 `.local/data.backups/`，容器目录为 `/data/store.backups/`。目录以私有模式创建，Windows 实际访问控制仍取决于运行账号和 ACL。

服务端在维护屏障内使用 `VACUUM INTO` 生成独立数据库快照，源库逻辑内容不变，再流式读取 `objects/` 和 `staging/` 普通文件并记录大小/SHA-256。格式 2 的数据库、对象、暂存及链段均写为认证密文；临时明文 SQLite 只放在受保护的数据根目录，处理结束清理。SQLite 快照语义见 [SQLite VACUUM INTO](https://www.sqlite.org/lang_vacuum.html)；文件对象与数据库的一致点由应用屏障共同保证。

`audit/segment-000000.json` 等逻辑条目每段最多 1000 行，保留原序号、事件、前驱及摘要，不重算原链；业务库仍保留全历史。完成前核对数据库完整性、清单摘要、文件元数据、任务确认偏移、链段和链尾检查点。

先写隐藏的 `.backup-编号.partial`，全部校验通过后才改名为 `backup-编号`。异常目录、符号链接和不安全路径拒绝；失败副本不展示为成功，但仍占用份数和容量。旧副本和失败副本由维护者检查处理，不自动删除。返回的 `bytes` 不含清单自身，总预算检查包含清单及已有副本实际字节。

备份含口令散列、账号状态、公钥、邀请摘要、文件内容、任务和授权等敏感数据，原最小版使用明文；当前候选新备份将上述内容及内层清单加密，旧副本不追溯改写。备份不含网关 CA/私钥、外部配置或数据库根目录外的初始化账号资料；这些需分别保护。数据备份不等于整台服务器恢复包，不纳入源码或公开演示附件。

## 4. 本机维护命令

开发环境使用 `npm run maintenance --`，生产容器可用 `node build/scripts/maintenance.js`。`--accounts` 指向受保护账号 JSON，默认选 `admin`，可用 `--admin` 指定其他现有管理员。工具不打印口令；改密后由维护者提供有效资料，不能把口令放入命令参数。

```powershell
npm run maintenance -- status --origin https://localhost:18443 --ca .local/container-check/ca.crt --accounts .local/container-check/accounts.json
npm run maintenance -- backup --origin https://localhost:18443 --ca .local/container-check/ca.crt --accounts .local/container-check/accounts.json
```

工具强制 HTTPS/WSS 和标准证书验证。副本由服务端写入配置目录，命令只返回结果；容器维护者再把具体副本复制到受保护的宿主机或独立介质，不覆盖已有副本。

独立检查点应在宿主机保存，目标目录不能挂载给应用：

```powershell
npm run maintenance -- anchor --origin https://localhost:18443 --ca .local/container-check/ca.crt --accounts .local/container-check/accounts.json --destination .local/independent-checkpoints
```

添加 `--interval-seconds 60` 可作为宿主机定期导出进程运行，间隔范围 10 秒至一天；工具不自行注册系统计划任务。检查点按序号/摘要命名，排他创建，不覆盖。认证会新增审计，因此多次运行的检查点通常不同。

本机直接运行时，换目录不自动形成权限隔离；同一 Windows 账号可能改写两个位置。应使用独立账号/受保护介质，或容器应用无法访问的宿主机目录。清单摘要用于完整性核对，外部检查点约束其锚定的审计历史，不能替代介质访问控制或证明不受信任备份的来源。

## 5. 隔离校验与恢复

使用备份形成之前的可信检查点核对。比备份更新的检查点不应要求旧快照包含，使用错误应失败。以下编号和摘要为占位，执行时替换为实际值：

```powershell
npm run maintenance -- verify --source .local/backup-copy/backup-实际编号 --key-file .local/protected/data.backup-keys --anchor .local/independent-checkpoints/checkpoint-实际序号-实际摘要.json
npm run maintenance -- restore --source .local/backup-copy/backup-实际编号 --target .local/restore-new --key-file .local/protected/data.backup-keys --anchor .local/independent-checkpoints/checkpoint-实际序号-实际摘要.json
```

读取格式 2 必须提供对应密钥；旧明文格式需显式加 `--allow-plaintext yes`。离线校验需要受保护的临时明文数据库，可用 `--temporary-dir` 选择已有可信目录，不能放在源备份中。密钥初始化/轮换及丢失处理见[备份加密与密钥管理](备份加密与密钥管理.md)。

恢复目标必须不存在，连空目录也不覆盖，不要指向当前 `DATA_DIR`。校验失败不创建目标；复制中故障留下 `.restore-incomplete`，应用拒绝启动，原库和原备份不变。应排查原因并另选新目录恢复，不能删除标记把未完成副本当作成功数据。

恢复后在独立入口验证原账号、文件摘要、任务偏移、有效/已撤销授权和审计检查点。正常启动撤销快照旧会话，不延续旧 WSS 身份。正式替换需另行安排停止写入、回退副本和配置切换，工具不自动替换正在运行的卷。

## 6. 验收边界

临时 TLS/WSS 套件覆盖并发总预算、磁盘测量失败/低余量、清理竞争/失败、审计容量及写入故障、备份屏障和恢复。ENOSPC 为受控故障注入，不填满真实卷；短写、零写入和 sync 失败分别验证确认偏移。路径错误、物理压力和逻辑预算是不同场景。
