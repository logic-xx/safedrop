## 准备

1. 保持 `safedrop-check` 容器运行，用桌面 Edge 或 Chrome 打开 `https://localhost:18443`。
2. 首次连接前，核对并信任本次验证容器导出的 CA 公共证书：`.local/container-check/ca.crt`。Windows 可打开该证书，选择“安装证书”，安装位置选“当前用户”，证书存储选“受信任的根证书颁发机构”。信任后重新打开浏览器连接，确保页面正常通过证书验证。
3. 在自己的电脑查看 `.local/container-check/accounts.json`，使用该容器生成的账号。它与本机直接运行模式的 `.local/accounts.json` 是不同文件，口令可能不同。截图和录屏中不展示口令。
4. 准备专门测试的中文名文件、空文件，以及至少三个约 32 MiB 的文件。使用 `Get-FileHash -Algorithm SHA256 -LiteralPath '文件完整路径'` 记录源文件与最终下载文件摘要。

| B09 | 使用 admin 查看安全事件、校验审计链，并导出日志及检查点 | 能看到实际操作记录；原始日志校验成功；界面可查看自动安全验证报告 | 通过：页面展示实际登录、上传与下载事件；84 条记录的当前链校验通过；两个导出 JSON 的离线校验及独立保存的检查点对照通过；页面已刷新显示 2026-11-17 生成的 28/28 报告 |

上传和下载共用最多三个活动任务。B03 应先完成一个较大文件的上传，再安排两个上传及一个下载，便于观察真正的双向并发。

B05 的原生磁盘续传应在支持文件保存权限的桌面浏览器完成。普通 Blob 下载路径仅支持 32 MiB 以内文件，不具备相同的磁盘恢复能力。异常终止时可能只能恢复到最后一个 4 MiB 检查点，不能要求所有未提交字节都被保留。

用于公钥登录的本机私钥保存在绑定时的浏览器数据中，更换浏览器或隐私窗口后不会自动具有该设备的私钥。B07 的第二个标签页可以使用口令登录。

普通/VIP 默认总限速分别为 1/4 MiB/s，上传、下载和多个连接合计，包含首块突发额度。用较大文件的持续传输耗时比较，记录文件大小、账号类型、任务数和耗时，避免用瞬间峰值判定。

本轮速率样本来自页面已确认进度，大小单位为 MiB（界面中的 MB 按 1024 换算）：

| 账号及任务 | 采样增量与时间 | 结果 |
| --- | --- | --- |
| alice，64 MiB 文件单上传 | 从 12.75 MiB 到 33.5 MiB，20.762 秒 | 约 0.999 MiB/s |
| alice，两个 32 MiB 上传和一个 64 MiB 下载 | 三个任务在 28.471 秒内各增长 9.5 MiB，合计 28.5 MiB | 合计约 1.001 MiB/s |
| bob，同一个 64 MiB 文件单上传 | 12:01:43.045 时已确认 6.25 MiB；页面完成事件为 12:01:57（秒级精度），剩余 57.75 MiB 约耗时 13.955～14.955 秒 | 估算约 3.86～4.14 MiB/s，与 4 MiB/s 档位一致 |

bob 的下一次进度观察发生在 12:02:00.867，文件此时已经完成，因此不能把完整的 17.822 秒观察间隔当作精确传输耗时。按这个间隔只能得到至少约 3.24 MiB/s 的保守下界；上表的估算另外使用了页面完成事件的时间。时间对照基于同一台宿主机的本机浏览器及容器时钟。本轮用于验证档位差异与账号聚合约束，不作为长期性能基准。
