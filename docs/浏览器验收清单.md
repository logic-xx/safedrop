# SafeDrop 浏览器验收清单

本清单用于记录真实浏览器操作。最近一轮于 2026-11-17 在 Microsoft Edge、独立验证容器 `https://localhost:18443` 上进行；容器脚本通过不自动代表这些界面流程通过。文件选择、磁盘保存对话框由使用者操作，其余界面流程与结果由浏览器复核。

## 准备

1. 保持 `safedrop-check` 容器运行，用桌面 Edge 或 Chrome 打开 `https://localhost:18443`。
2. 首次连接前，核对并信任本次验证容器导出的 CA 公共证书：`.local/container-check/ca.crt`。Windows 可打开该证书，选择“安装证书”，安装位置选“当前用户”，证书存储选“受信任的根证书颁发机构”。信任后重新打开浏览器连接，确保页面正常通过证书验证。
3. 在自己的电脑查看 `.local/container-check/accounts.json`，使用该容器生成的账号。它与本机直接运行模式的 `.local/accounts.json` 是不同文件，口令可能不同。截图和录屏中不展示口令。
4. 准备专门测试的中文名文件、空文件，以及至少三个约 32 MiB 的文件。使用 `Get-FileHash -Algorithm SHA256 -LiteralPath '文件完整路径'` 记录源文件与最终下载文件摘要。

| B02 | 上传中文名文件和空文件，再分别下载 | 文件名正确；空文件可完成；下载与源文件摘要一致 | 通过：784 字节中文文件与空文件的下载 SHA-256 均一致；空文件进度条修复后复验通过 |
| B03 | 先上传一个较大文件，再同时启动两个上传和该文件的下载 | 同屏出现三个任务；上传与下载进度交错推进；最终摘要正确 | 通过：两个 32 MiB 上传与一个 64 MiB 下载同时推进；两个上传完成后的服务端摘要与源文件相同，磁盘上的并发下载文件与源文件逐字节一致 |
| B04 | 大文件上传到中途暂停，再继续；另一次在中途刷新并重新登录、重新选择相同文件 | 从已确认位置恢复，而非始终从零开始；最终摘要一致 | 通过：64 MiB 文件先在 8.5 MiB 暂停后继续；34 MiB 再次暂停、刷新并重选，恢复后到 34.75 MiB；最终上传完成，下载到磁盘后的 SHA-256 与源文件一致 |
| B05 | 大文件下载到中途暂停，再恢复；另一次暂停后刷新、重新登录并恢复下载 | 按提示重新授权目标文件；沿用已保存位置；最终文件摘要一致 | 通过：4.75 MiB 暂停、同页恢复至 52.75 MiB 后暂停；刷新并登录后从 52.75 MiB 恢复，再暂停和恢复时只有一条下载任务；最终磁盘文件为 64 MiB，逐字节和 SHA-256 均与源文件一致 |
| B06 | 在安全中心重新输入口令并绑定本机公钥，退出后使用公钥登录；再撤销公钥、退出并重新尝试公钥登录 | 绑定与公钥登录成功；撤销后的公钥登录被拒绝 | 通过：绑定、登录、撤销与拒绝均已操作；撤销后的错误提示已改为公钥认证提示并复验 |
| B07 | 在另一个独立浏览器标签页登录同一账号，从第一个标签页撤销该会话 | 被撤销标签页断开并退出业务界面；其他会话仍可操作 | 通过：两个标签页使用独立 WSS 会话；指定会话被撤销后退回登录页，原会话仍可操作并完成上传 |
| B08 | 分别使用 alice 和 bob 传输相同大小的大文件；同一账号同时开启多个任务 | 普通与 VIP 的持续速率有差异；增加任务不绕过账号总限速 | 通过：alice 单上传持续样本约 1.00 MiB/s；两个上传与一个下载的合计速率约 1.001 MiB/s；bob 的同一个 64 MiB 文件持续速率按完成事件的秒级时间估算约 4 MiB/s，详见下方样本范围 |
| B09 | 使用 admin 查看安全事件、校验审计链，并导出日志及检查点 | 能看到实际操作记录；原始日志校验成功；界面可查看自动安全验证报告 | 通过：页面展示实际登录、上传与下载事件；84 条记录的当前链校验通过；两个导出 JSON 的离线校验及独立保存的检查点对照通过；页面已刷新显示 2026-11-17 生成的 28/28 报告 |

上传和下载共用最多三个活动任务。B03 应先完成一个较大文件的上传，再安排两个上传及一个下载，便于观察真正的双向并发。

B05 的原生磁盘续传应在支持文件保存权限的桌面浏览器完成。普通 Blob 下载路径仅支持 32 MiB 以内文件，不具备相同的磁盘恢复能力。异常终止时可能只能恢复到最后一个 4 MiB 检查点，不能要求所有未提交字节都被保留。

用于公钥登录的本机私钥保存在绑定时的浏览器数据中，更换浏览器或隐私窗口后不会自动具有该设备的私钥。B07 的第二个标签页可以使用口令登录。

普通/VIP 默认总限速分别为 1/4 MiB/s，上传、下载和多个连接合计，包含首块突发额度。用较大文件的持续传输耗时比较，记录文件大小、账号类型、任务数和耗时，避免用瞬间峰值判定。

本轮速率样本来自页面已确认进度，大小单位为 MiB（界面中的 MB 按 1024 换算）：

| 账号及任务 | 采样增量与时间 | 结果 |
| --- | --- | --- |
| alice，64 MiB 文件单上传 | 从 12.75 MiB 到 33.5 MiB，20.762 秒 | 约 0.999 MiB/s |
| alice，两个 32 MiB 上传和一个 64 MiB 下载 | 三个任务在 28.471 秒内各增长 9.5 MiB，合计 28.5 MiB | 合计约 1.001 MiB/s |
| bob，同一个 64 MiB 文件单上传 | 12:01:43.045 时已确认 6.25 MiB；页面完成事件为 12:01:57（秒级精度），剩余 57.75 MiB 约耗时 13.955～14.955 秒 | 估算约 3.86～4.14 MiB/s，与 4 MiB/s 档位一致 |

bob 的下一次进度观察发生在 12:02:00.867，文件此时已经完成，因此不能把完整的 17.822 秒观察间隔当作精确传输耗时。按这个间隔只能得到至少约 3.24 MiB/s 的保守下界；上表的估算另外使用了页面完成事件的时间。时间对照基于同一台宿主机的本机浏览器及容器时钟。本轮用于验证档位差异与账号聚合约束，不作为长期性能基准。

## 本轮问题修复

| 问题 | 修改 | 复验 |
| --- | --- | --- |
| 切换账号后仍显示上一账号的传输任务名 | 队列绑定账号，退出清空任务；文件请求及响应绑定创建它的会话；忽略旧连接的迟到回调 | 浏览器切换 alice → bob，bob 文件列表和任务队列均为空；四项会话竞争回归通过 |
| 空文件完成后进度条仍为空 | 零字节文件完成时使用完整进度值 | 浏览器显示 100%，进度值与上限均为 1 |
| 撤销公钥后登录失败提示仍指向口令 | 公钥登录使用对应的认证失败说明 | 浏览器拒绝撤销后的公钥，并显示公钥认证提示 |
| 恢复下载新增任务，旧暂停条目仍保留 | 复用该文件的暂停任务；等待文件授权时禁用重复点击 | 更新容器后，在 56.75 MiB 暂停并恢复，队列始终只有一条下载任务，最终完成 |

## 留存记录

每项记录浏览器版本、时间、操作步骤、结果及必要截图。失败项保留报错原文和恢复位置，修复后再更新状态。文件摘要、会话撤销结果和续传起点应能与截图或记录对应。

截图及录屏可以包含测试文件名、进度、拒绝事件和结果；账号口令、私钥及真实敏感文件内容应留在本机。
