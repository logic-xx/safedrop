按《实验 1 讲解 2026.pdf》第 2～3、33 页，实验 1B 于北京时间 2026-11-24 23:55 前交课程网站。使用未加密 ZIP，报告含 Git 链接，源码保留完整的可核查远端 Git 历史。若课程网站后发要求有变化，按后发要求处理。

源码 ZIP 用于解出源码目录，报告 PDF 已按讲义允许的格式准备。按姓名学号重命名并加入真实 MP4 后再形成课程总 ZIP。证据 ZIP、SHA-256 和版本清单属于并列留存材料，课程讲义列出的提交内容为上述三项。课程讲义未规定视频硬性分钟数，报告使用默认 A4 排版。源码内的仓库 README 作为项目文档随源文件保留，课程文件夹根无需添加 README。

项目仓库为 [logic-xx/safedrop](https://github.com/logic-xx/safedrop)。最终交付提交由使用者推送，提交前应核对 Git 链接和课程评阅者所需的可访问状态。记录中的 GitHub Actions 证据对应已推送的验收代码；文档交付提交无新业务代码。

## Windows 复现检查点

1. 将交付源码从 ZIP 解到独立目录。记录 Windows、Node、npm、OpenSSL、浏览器版本；如走 Compose，另记录 Docker Desktop/Compose 与 Linux x64 引擎。对照交付清单复算 ZIP 的 SHA-256。
2. 按[运行与验收](运行与验收.md)完成 `npm ci`、`npm run setup`、`npm run build`、`npm start`。核对 Node 24.x、OpenSSL 路径及本地 CA 信任。浏览器访问 https://localhost:8443，验证首页和支持的浏览器原生存盘权限。正常文件读取还要求本机扫描器与合规签名，或采用现有 Compose 配置。
3. 在专用目录运行 `npm test` 与 `npm run security:report`，逐项记录跳过原因；按[浏览器验收清单](浏览器验收清单.md)和[演示脚本](演示脚本.md)验证上传、保存、续传、扫描、授权与时间线。测试报告新旧不得混用。
4. 若需新环境容器复现，在该专用环境的普通 PowerShell 先执行 `./scripts/verify-container.ps1 -CheckOnly`，确认依赖、Compose 配置和扫描器资源。引擎就绪后执行完整脚本；命名验收项目和数据卷需属于该专用环境。现有 `safedrop-check` 原卷无需为本阶段重跑。
5. 按[存储维护与恢复](存储维护与恢复.md)和[备份加密与密钥管理](备份加密与密钥管理.md)先留可信独立检查点，另存加密副本与独立密钥，校验并恢复到不存在的目标目录，核对 SQLite 完整性、样本摘要和审计。正式账号和原文件不参与录制。

全新 Windows 机器复现目前待补。本机新目录的解包、文件校验和构建只证明当前主机上的源码包复现步骤。发布清单记录该批 ZIP 的实际提交、文件数、摘要和检查结果。

## 包件与披露

源码包用目标 Git 提交树生成，排除 Git 元数据、运行卷、安装/构建缓存、原始报告、系统或浏览器凭据、备份及本地数据。证据包使用[交付证据索引](交付证据索引.md)的来源说明与脱敏内容，截图保留界面结果、遮盖可关联标识；压缩包的 SHA-256 与各内部文件摘要分别记录。官方 CI ZIP 只在下载后匹配官方摘要并安全解包时计为完成本机归档。
