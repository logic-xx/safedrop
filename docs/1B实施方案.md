## 3. Web 技术方案

- 前端：Vue 3 + TypeScript，提供文件浏览、传输队列、账户与公钥管理、连接和安全状态。
- 后端：Node.js + TypeScript，提供 HTTPS、WSS、认证、文件服务、权限检查、配额和审计。
- 数据库：SQLite 存储用户、密钥绑定、文件元数据与续传任务；全部动态值使用参数绑定，动态排序字段采用固定白名单。
- 通信：HTTPS 加载页面及必要的账户接口，WSS 承载主要文件传输业务及自定义应用层协议；二进制分块避免 Base64 膨胀。
- 部署：先保证 Windows 本地构建运行，再提供 Docker Compose。反向代理的空闲超时应与 WebSocket 保活策略匹配。
- 密码学：使用标准 TLS、Web Crypto / Node.js crypto；不自行编写加密算法。口令用带盐的专用口令散列存储。

本机初步环境检查：Node.js v24.14.0 已安装；Docker 客户端已安装，但检查时容器引擎未运行；目录尚未建立 Git 仓库。依赖版本在正式初始化时核验并锁定，此处不声称已验证兼容性。

### 3.1 长连接如何满足课件

浏览器客户端设置独立连接管理器，负责建连、应用心跳、失效检测、重连退避和任务恢复。Node.js 服务端对底层 socket 明确设置 `setKeepAlive(true, ...)`，并用 WebSocket ping/pong 检测断线。文件完成后维持连接，不发送关闭连接作为完成标志。

HTTP 的 `Connection: keep-alive` 不足以独立证明满足要求。正常在线时维护长连接；网络中断或超时后应恢复连接，而不是承诺 TCP 在断网时仍能保持。浏览器没有独立 OS 守护进程，后台标签页也可能被系统冻结，报告须准确说明客户端连接管理组件的运行范围。若验收把“守护进程”严格限定为独立进程，则增加本地连接代理，而不是把页面定时器写成独立守护进程。

主要文件块也走同一 WSS 通道，避免只有一个闲置 WebSocket，而实际传输仍是每次新建的短连接。通过任务标识交错传输不同文件块，限制每个任务窗口，确保慢任务不长期挤占心跳和控制消息。

### 3.2 公钥认证如何落地

Web 方案初步选用标准 P-256 签名，由浏览器 Web Crypto 与服务端标准库完成。正式实现前验证双方签名编码一致。

1. 用户先用可信账户流程绑定自己的公钥；绑定、替换、撤销都要求重新认证并记审计日志。
2. 服务端生成不可预测、短时有效且只能使用一次的挑战，并绑定用户、连接、用途和挑战标识。
3. 客户端用私钥签名约定的规范编码内容；服务端用已绑定公钥验签并原子消费挑战。
4. 认证成功后建立与连接绑定的会话，后续每条业务消息继续做授权。

服务端不能信任客户端临时提交的任意公钥来证明已有账号身份。私钥不上传，不放入源码或普通 localStorage；优先使用不可导出的浏览器密钥，密钥生命周期、备份限制和设备迁移方式在设计中明确。

这属于应用层公钥认证，不应在报告中声称为双向 TLS。课件允许公钥身份认证或双向证书认证，并非必须二者同时实现。浏览器 mTLS 涉及证书导入与选择，现阶段不作为默认实现。

## 4. 自定义协议草案

暂定协议名 SFT/1。WSS 提供安全通道与消息边界；SFT/1 定义账号认证、权限、任务、块确认、续传和错误语义。报告要说明两者的分工，不能把 WebSocket 标准报文头当成自己设计的协议。

每个 WebSocket 二进制消息携带一个 SFT/1 报文：

`固定头 24 字节 | UTF-8 JSON 元数据 | 二进制载荷`

| 字段 | 字节数 | 说明 |
| --- | --- | --- |
| magic | 4 | 固定魔数，识别协议 |
| version | 1 | 协议版本 |
| type | 1 | 消息类型 |
| flags | 2 | 标志位，未定义位必须为零 |
| requestId | 4 | 关联请求与响应 |
| streamId | 4 | 当前连接内的传输任务标识，0 留给控制消息 |
| metadataLength | 4 | JSON 元数据字节数，具有严格上限 |
| payloadLength | 4 | 二进制载荷字节数，具有严格上限 |

多字节整数统一采用大端。任务持久化另用不可预测的 transferId，不依赖重连后会变化的 streamId。JSON 中的总文件大小和偏移必须是合法、安全范围内的整数。初步建议块大小 256 KiB、元数据上限 16 KiB；这些是待测试的工程参数，不是课件规定。

消息分组应覆盖：HELLO/版本协商、认证挑战/证明/结果、目录查询、上传初始化、下载初始化、DATA/ACK、续传查询与确认、完成请求/结果、暂停/取消、心跳、错误和退出。最终消息编号及状态迁移在正式协议文档固定。

必须解释并验证的正确性规则：

- 实际消息长度必须与头部声明一致，先检查上限再解析；未知类型、非法状态和越界偏移有明确错误。
- 接收方依据文件总大小、块偏移和显式完成消息判断结束，不依据关闭 TCP。
- ACK 表示的持久化保证必须定义清楚；续传偏移不得超过服务端可恢复的数据范围。服务端进程异常重启与断网是不同测试场景。
- 重复块、重复初始化和重复完成请求有幂等处理；确认丢失后不能重复追加文件内容。
- 上传先写隔离的临时文件，验证大小与完整文件 SHA-256 后原子发布；哈希验证失败时不能标成成功。
- 下载期间固定文件版本；续传前检查版本和本地已保存内容，避免把两个版本拼接。
- 认证与授权失败不能只在界面提示；服务端必须拒绝操作和非法任务访问。
- 控制帧与数据帧采用有界队列、流量窗口及背压，避免大文件导致内存无限增长。

浏览器下载续传先验证 Edge/Chrome 的安全上下文和本地文件写入能力；需重新选择或授权文件时必须在界面体现。若采用其他暂存方式，要明确配额与清理策略。不能把“刷新后重新从头下载”算作断点续传。

## 5. 安全实现与证据

| 威胁 | 实现重点 | 验证方式 |
| --- | --- | --- |
| 中间人 | HTTPS/WSS；验证证书信任链、主机名和有效期；本地 CA 仅用于受控实验 | 未受信任证书、主机名错误、失效证书连接失败；不使用忽略证书错误的启动参数 |
| SQL 注入 | 参数化查询；数据库访问集中封装；排序字段白名单 | 用含引号与注入语句的输入不能绕过登录或访问其他用户文件 |
| 越权与路径穿越 | 服务端所有权检查；物理文件用服务端生成的标识命名；显示文件名与物理路径分离 | A 不能访问 B 的文件或续传任务；`../`、绝对路径、Windows 路径变体不能越界 |
| 恶意文件 | 文件存储位于 Web 根目录外；不自动执行、解压或渲染上传内容；下载用附件语义与安全文件名 | 上传 HTML/脚本不会在同源页面执行；文件名按文本显示 |
| 重放与冒名 | 一次性挑战、过期时间、连接与用途绑定；公钥可信绑定 | 重复签名、跨连接复用、篡改用户标识均失败 |
| 应用层 DoS | 握手/认证/空闲超时；全局及每 IP/用户连接上限；消息大小、速率、文件大小、存储配额和并发上限 | 在本机或授权环境进行有界压力测试；记录限流拒绝数、CPU/内存及合法用户操作情况 |
| WebSocket 劫持 | 握手 Origin 白名单、认证、逐消息授权；退出/过期后使会话失效 | 非允许来源、未认证消息、注销后的业务消息被拒绝；Origin 不能代替身份认证 |
| 主机文件越界 | 非特权进程；只给数据目录必要写权限；只读代码/证书挂载；容器减权 | 用部署配置展示读写范围；容器隔离与应用权限检查分别验证 |

应用限流与配额只覆盖部分拒绝服务场景。链路被大流量打满时还需要上游防护，报告应明确这一能力边界；不能用本机少量并发测试宣称能抵御任意规模 DDoS。

日志记录事件、脱敏用户标识、任务标识、字节计数、错误类型和时间；不记录口令、私钥、会话凭据或文件内容。审计日志可导出，截图与记录使用同一测试编号。

## 7. 最小验收集

至少覆盖以下用例，并为每项记录环境、输入、操作步骤、预期、实际结果和证据路径：

1. 空文件、1 字节、跨块边界、中文名及同名文件；大文件不依赖整文件驻留内存。
2. 多用户并发上传/下载；一个用户失败不导致其他任务被关闭。
3. 同一连接上传、查询、下载，空闲期间仍保活；手动退出时主动清理。
4. 上传和下载分别中断恢复；重复块、确认丢失、错误偏移、源文件变化得到正确处理。
5. 服务端重启后的续传恢复；若尚未支持，应明确列为限制而非填“通过”。
6. 非法证书、公钥挑战重放、错误签名、未授权任务和过期会话被拒绝。
7. SQL 注入、目录穿越、超大报文、非法头部和错误状态不会绕过权限或使服务崩溃。
8. 普通/VIP 稳定限速比较；增加任务或连接不能绕过同一用户的总限速。
9. 配额用尽、磁盘写入失败、传输取消后有明确错误和资源清理。
10. 全新目录从源码构建并运行；部署脚本与报告命令一致。

测试只对本机或明确授权的实验环境执行。测试数据和结果必须来自真实运行；吞吐量等数值注明文件大小、并发、机器、网络、采样方法和重复次数。
