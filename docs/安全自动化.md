## 工作流与执行边界

配置为 [security.yml](../.github/workflows/security.yml)，在 main 推送、PR、手动触发及每日 UTC 02:23（北京时间 10:23）执行。推送由使用者手动完成，没有自动推送、发布、镜像上传或生产部署。分支保护规则未自动配置，工作流失败本身不等于仓库已禁止合并或推送。

| 作业 | 范围 | 失败条件 |
| --- | --- | --- |
| verify | Ubuntu 24.04 / Windows 2025、Node 24.22.3；锁文件安装、生产构建、自动测试；Ubuntu 另生成 TLS/WSS 安全场景报告 | 任意安装、构建、测试或报告命令失败 |
| source-security | 工作流静态检查、开发/生产依赖审计、当前源码和全部可达 Git 历史的凭据检查、真实扫描器的合成令牌检出/脱敏自测 | 命令或网络失败、报告无效、未处理高/严重风险、例外过期、凭据发现、私密/生成文件进入源码范围或自测失败 |
| image-security | 在隔离 CI runner 复用容器验证脚本实际构建、运行和重启应用/网关，核对权限、严格 HTTPS/WSS、MFA 及备份恢复；随后扫描已验的本地应用镜像及公开网关镜像 | 功能验证、构建/扫描失败、报告无效、任何高/严重漏洞，包括尚无修复版本的漏洞 |

GitHub Actions 权限仅为 `contents: read`；checkout 不保留认证凭据，凭据检查要求完整历史。没有 `pull_request_target`、仓库秘密注入或将不可信 PR 插值成命令。Action 使用完整提交 SHA；扫描器使用固定版本和独立记录的 SHA-256，先验证下载归档再提取执行，HTTPS 保持标准证书验证。固定 runner 标签不代表 runner OS 镜像内容完全不变。

提交 `11c7eb1` 的首次真实 CI 已结束：Ubuntu、Windows 构建测试和源码安全作业成功，业务安全报告 131/131；最终应用镜像 71 条高/严重记录、网关 2 条，镜像作业失败。**第 17 项尚未全部验收。** 具体计数、跳过范围、制品摘要及风险处置见[镜像风险与修补](镜像风险与修补.md)。当前应用运行时修补候选已在本地 Node 24.22.3 下通过构建及 27 项测试，其基础镜像扫描零高/严重；新打包镜像的运行、扫描及旧数据卷升级仍待取得证据。

新应用镜像需由 CI runner 实际运行并扫描，再由使用者安排保留原卷的升级验收；基础镜像扫描不覆盖最终应用内容。镜像目前没有风险例外，没有使用 `--ignore-unfixed`，已知风险会使对应检查失败，不能因功能容器验收通过就标为漏洞扫描通过。原运行镜像、数据卷、账号及前端资源尚未部署本轮候选，本地工具不访问 Docker 引擎。

工具归档校验值在 [tools.json](../scripts/ci/tools.json)，下载仅来自对应上游 GitHub Releases，不运行远程安装脚本。更新工具或 Action 时重新核对官方 Release、标签提交及归档摘要，再运行对应检查；不自动使用浮动 `latest`。工具缓存位于忽略提交的 `.local/ci-tools`，宿主机及运行账号仍属于信任边界。

## 本地检查

需 Node.js 24.14+（24.x）、npm、Git；下载工具还需网络与 `tar`。Windows 5.1 的系统下载组件若无法验证远程证书，仍使用 Node 的标准 HTTPS 下载，不关闭 TLS 检查或改客户端信任配置。

```powershell
npm run ci:workflow
npm run ci:audit
npm run ci:secrets
npm run ci:scanner-test
npm run ci:artifacts
```

凭据扫描先拒绝 `.local`、`tmp`、`reports`、生成目录、账号资料、部署密钥等进入源码范围，再扫描当前非忽略文件的独立快照及全部可达历史。符号链接和非普通文件拒绝处理，不跟随到本机私密目录。未跟踪但未忽略的新源码也会扫描。内联 `gitleaks:allow` 不会跳过检查；目前没有通配测试目录或整类凭据的例外。

原始 Gitleaks 输出启用 100% 脱敏，另在公开结果中仅保留规则、相对文件路径、行号及提交/指纹，不发布 Match/Secret 字段。正向自测使用本地临时合成令牌，确认工具确实检出且报告不包含令牌原文；普通 `npm test` 未指定扫描器时，此项明确标为跳过，`ci:scanner-test` 则实际下载并执行已校验的扫描器。

有权访问本机 Docker 引擎时，可先构建独立镜像再检查；不需要启动业务容器或挂载数据卷：

```powershell
docker build --tag safedrop:ci .
npm run ci:image -- safedrop:ci
npm run ci:image -- caddy:2.11.9-alpine remote
```

`remote` 只用于公开镜像仓库。扫描进程使用自己生成的空 Docker 登录配置下载公共漏洞库和公开镜像，不读取本机个人凭据助手，不修改既有 Docker 配置，也不授予引擎访问权限。扫描器库下载失败或引擎无权访问时结果为失败，不能报告零漏洞；按当前工具边界使用 CI runner 或由使用者在普通终端执行。仅扫描远程 Node 基础镜像不等于最终应用镜像已通过。

CI 实际功能容器完成后运行 `ci:runtime-report`，仅接纳完整通过的容器报告及实际已修补 Node 24 的证明，导出脱敏汇总。该命令本身不访问引擎，也不能把旧报告转换成新镜像验收结果。

Windows 扫描进程的临时路径同样放在项目内 `.local/ci-temp`，避免默认受限临时路径含 `#` 时触发 Go 文件 URL 解析错误；只设置该子进程的 TEMP/TMP/TMPDIR，不修改系统环境或权限。先前凭据助手及临时路径失败保留在验证记录，随后已成功完成公开镜像扫描并得到真实漏洞结果。

## 已知依赖风险及限时处理

2026-11-18，生产依赖 `npm audit --omit=dev` 返回零告警。全部依赖审计发现开发构建链中的 **picomatch 4.0.7 / GHSA-fc5q-39xc-vjpf**，上游公告明确暂无修复版；影响可能沿 Vite、Vue 类型检查等依赖关系产生多条高风险记录，这不是多项独立漏洞。

当前仓库未将用户提供的 glob 表达式传入该构建工具，生产安装也不包含 picomatch；据此在 [exceptions.json](../scripts/ci/exceptions.json) 记录一项开发范围的临时风险接受。**这不是修复，也不表示全部依赖无漏洞。** 规则同时核对公告 URL、包名、严重程度、精确安装版本、每个安装节点的 `dev: true`、理由及期限；生产高/严重漏洞没有例外。新增公告、版本/用途变化或例外过期均失败。

期限为 **2026-11-25 00:00（北京时间）**。届时若仍有该公告且未更新修复版，检查自动失败；应提前复核上游并实测升级，不自动延期、扩大例外或执行 `npm audit fix --force`。原始风险记录及本轮结果保存在忽略提交的 `reports/`，摘要见[验证记录](验证记录.md)。

## 证据与结果判读

检查生成 `reports/ci/` 下的 JSON，包含开始时间、Git 基线、工作区是否有修改、Node/平台及 CI run ID。凭据结果另记录当前源码摘要；镜像结果含实际镜像标识、漏洞库信息及扫描范围。新检查先移除本项旧成功报告；执行错误生成 `failure-*.json`，避免把旧成功当成新结果。

GitHub 仅上传明确列出的 `reports/latest.json` / `.html` 及 `reports/ci/*.json`，保留 14 天。上传前 `ci:artifacts` 另使用真实扫描器检查这些文件；发现凭据、扫描失败或非普通文件时，上传步骤不会执行。此次本地注入合成令牌已确认上传检查拒绝并移除旧成功结果，清理样本后正常报告重新通过；该证明不包含令牌原文。

不会打包整个 `reports`、`.local`、`tmp`、账号、测试证书、业务文件或备份。原始扫描诊断和工具缓存留在本机忽略目录，不上传。各作业互不掩盖失败，完整结果以对应提交的实际 Actions run 为准。

本机 Windows 检查不代表 Ubuntu/Windows hosted runner 已运行；静态工作流通过不代表远端 CI 成功；运行时容器功能验收与漏洞扫描是不同证据。最新实现及待补范围见[验证记录](验证记录.md)及[安全验证矩阵](安全验证矩阵.md)。
