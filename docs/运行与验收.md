# SafeDrop：运行与验收

2026-11-22 安全事件浏览改版已在本机及独立 Edge 夹具验收。后续 `28a3f4f` 的真实 CI 版本 12 和本机版本 12 原卷均通过，保留 1062 条原记录及账号、CA、独立备份密钥和原 MFA 设置，数据库仍为版本 7。证据见[交付证据索引](交付证据索引.md)。

安全中心现在优先展示事件浏览：选择最近 1 小时/24 小时/7 天，或输入本机时区的起止时间后“应用时间”，范围最多 31 天，结束时间不包含在内。横轴显示完整可见范围的数量，点击时间段放大，左右拖动或“更早/更晚”平移，放大后可返回上一范围。下方按审计序号从新到旧分页，点事件查看详情，窄屏在下方展开，可用关闭按钮或 Escape 返回。手动“刷新事件”或顶部“刷新数据”更新快照；后台轮询保留正在阅读的记录。

部署探针包含 `events.query` 的匿名拒绝、权限、范围分布、响应预算及快照分页检查。CI 新 Linux 容器和本机原卷均取得重启前后结果，工具另外从原卷入口补核严格 HTTPS/WSS。纯文档改动无需重建。

SafeDrop 是一个支持加密文件传输、断点续传、公钥认证、会话控制和可校验审计的 Web 项目。本文介绍本地运行、容器部署和安全验证；协议与边界见《协议与安全设计.md》。

## 1. 本机启动

需要 Node.js 24.x、npm 和 OpenSSL；推荐使用已修补的 24.22.3 或更新 24.x。本地 API 兼容下限仍为 24.14，当前容器验收另要求实际 Node 至少为 24.22.3。首次运行在项目目录执行：

```powershell
npm ci
npm run setup
npm run build
npm start
```

然后访问 **https://localhost:8443**。

文件扫描需要独立 ClamAV 1.5.5、官方签名库及受保护的 `CLAMD_HOST`/`CLAMD_PORT`。未配置或检查失败时不会放行文件。Compose 已加入独立扫描器，需额外预留 4 GiB 内存和签名卷；本机升级曾在官方包下载超时而停止。验收脚本新增宿主机固定包缓存/续传和命名上下文，提取前仍校验原摘要；6437f71 的真实 Linux CI 已验证该路径、真实引擎/API 和三镜像门槛。本机版本 10 原卷已通过，保留 874 条原记录及账号/CA/独立密钥；实际入口、新资源、SQLite 6 加密恢复和 Edge 新维护页补核通过。旧文件保留但需所有者首次请求扫描。配置、首次启动耗时和边界见[文件扫描与隔离](文件扫描与隔离.md)。

- 初始化会生成 `admin`、`alice`、`bob` 三个账号，分别用于管理员、普通用户、VIP 用户。每次新环境的口令随机生成，保存在 `.local/accounts.json`。请在本机自行查看，不要公开该文件。
- 初始化不会覆盖已存在的账号、文件或证书。
- 本地 CA 公共证书位于 `.local/tls/ca.crt`。浏览器首次使用前，需要由使用者核对来源后将这个证书导入当前用户的受信任根证书存储。不要导入 `ca.key`；不要通过关闭证书验证来使用程序。
- CA 私钥和服务器私钥在 `.local/tls/`，已排除在 Git 和镜像构建上下文之外。该目录应仅供部署维护者访问。
- OpenSSL 不在 PATH 时，可先设置 `$env:OPENSSL_PATH='实际的 openssl.exe 完整路径'`。
- 已在 Node v24.14.0 和 v24.22.3 实测；SQLite 提示随 Node 版本不同。升级 Node 主版本前需重新测试，运行时修补及剩余风险见镜像修补说明。

未开启管理员 MFA 的账号可在“安全中心”重新输入口令并绑定本机公钥，以后同一浏览器可使用公钥登录。私钥通过 IndexedDB 保存为不可导出的 CryptoKey，清理浏览器数据或更换设备后需要重新绑定。管理员启用 MFA 后改用口令加验证码，旧公钥撤销且不能替代双因素。撤销公钥与撤销已登录会话是两个独立操作；必要时分别执行。

### 1.1 账号与邀请

管理员登录后进入“账号与邀请”，生成 1～168 小时有效的单次邀请（默认 24 小时）。令牌只展示本次，请通过可信渠道交给受邀者。受邀者在登录页选择“使用邀请注册”，自行设置 3～32 位账号和 12～256 字符口令；创建成功后单独登录。注册得到标准普通用户权限。已使用、到期或撤销的邀请不可领取；同一个邀请并发领取只允许一人成功。邀请码不应放入公开截图、录屏或 Git。

默认邀请注册。管理员可关闭自助注册，关闭期间所有邀请都不能领取；重新开启后未到期、未使用、未撤销的邀请继续有效。管理员可分页查看邀请状态、撤销未使用邀请和停用账号。管理权限不包含其他用户的文件读取或任务操作权限。

所有用户可在“安全中心”修改自己的口令。修改成功会退出全部会话、停止传输并撤销全部公钥绑定，请使用新口令登录并按需重新绑定设备。文件和未完成上传保留。原始 `accounts.json` 仅记录初始化资料，修改口令后其中的旧口令不再有效，程序不会将新口令回写该文件。

停用账号后口令、公钥和旧会话都不能继续使用，等待中的上传下载被取消，业务文件与任务仍然保留。界面要求输入目标账号确认；服务端独立阻止停用最后一名可用管理员。本版不提供重新启用、忘记口令重置、角色提升、开放注册和账号自动恢复，部署维护者应保管好可用管理员的登录资料。

### 1.2 更新已有安装

先停止本次验证入口上的文件操作，再更新应用。启动时自动执行 SQLite 增量迁移，无需清库、删除数据卷或重新初始化账号；新增字段不改变原口令散列、文件所有权、任务偏移或审计链。当前授权到期候选版本号为 `PRAGMA user_version=7`：版本 0 增加账号策略，版本 1 增加删除意图，版本 2 增加独立交付授权表及索引，版本 3 增加上传活动时间表，版本 4 增加 MFA 四张表，版本 5 只新增 file_scans 表及队列索引，版本 6 在 deliveries 增加默认 0 的 expires 列及到期索引；历史授权保留原期限规则。原数据与审计行不重建，不自动给管理员开启 MFA。保留现有持久化数据目录和命名卷；不要使用 `down -v`、删除 SQLite 文件或删除对象目录来升级。启动后的旧会话按既有规则失效，用户重新登录即可。

### 1.3 管理员双因素认证

管理员可在安全中心自行绑定基于时间的六位验证码。绑定密钥应添加到独立验证器应用，本页只填验证器生成的六位数字；准备五分钟到期不会自动开启或更改已有因子。启用后每次登录需要口令和新验证码，恢复码仅进入重新绑定流程，不能直接进入业务。请安全保存一次性恢复码。

部署者应独立保护并备份 `MFA_KEY_FILE`（默认 `DATA_DIR` 加 `.mfa-key`）；普通数据备份不包含此加密密钥。已开启 MFA 后，缺失或错误密钥会使启动失败，不能通过删 MFA 表或重新生成随机密钥恢复访问。维护命令支持 `--otp-file`，周期检查点复用一次验证后的连接，过期或断线需重新认证。详见[管理员双因素认证](管理员双因素认证.md)。

## 2. 文件传输

- 同时选择多个文件即可创建任务，界面最多并发运行三个任务。上传与下载共用同一条 WSS 连接及账号总速率额度。
- 上传中断后，可在重新登录后重新选择相同文件继续。服务端校验名称、大小、完整文件摘要与任务所有权。界面可取消未完成任务以释放配额。
- 下载续传推荐桌面 Edge/Chrome，并允许用户选择本地目标文件。每 4 MiB 提交一次磁盘检查点，正常暂停或可处理的断线会提交当前位置；浏览器异常终止时通常只能恢复到最后一个已提交检查点。
- 本地下载文件重新授权后，客户端计算已有前缀摘要，服务端核对后才接受续传位置。不能恢复到未保存或内容不一致的位置。
- 其他浏览器保留 32 MiB 以内的普通下载；不声称具备相同的磁盘续传能力。
- 默认单文件 512 MiB，每账号总文件与未完成上传预留空间 1 GiB，最多 16 个未完成上传，已完成文件与未完成上传合计最多 1000 个。普通/VIP 速率分别为 1/4 MiB/s，双向合计，允许首块突发。

### 2.1 文件管理与配额

上传完成仅确认大小、摘要和持久化，随后自动排队扫描；只有扫描通过且未超过默认 168 小时才可下载、续传或发送。旧文件在工作台点击“请求扫描”，失败后可重试；重新扫描立即阻止原下载和授权读取。隔离、等待或失败均保留原文件和占用，不自动删除；接收者无法自行重扫或强制放行。管理员维护页显示全局状态数量，没有代替所有者读取/放行的入口。

文件工作台展示服务端统计的已用、上传预留和可用空间，同时显示账号总配额、文件数及未完成任务数。未完成上传按声明的完整文件大小预留，并非只统计还没上传的字节；上传完成后转为已用。删除待重试仍计入已用，取消待重试仍计入预留。这里显示账号额度，不代表服务器磁盘可用容量。

在自己的文件行选择“重命名”，填写新名称并保存。文件标识、内容、摘要和续传位置不变；已保存的本地文件不会自动改名。非法名称会在操作表单内明确提示。

选择“删除”后，必须输入完整文件名确认。此操作永久删除服务器文件，没有回收站。删除会停止该文件尚未完成的下载和续传；已下载到本地的内容不受影响。只有磁盘清理和数据库事务都成功，记录才移除并释放额度。若显示“删除待重试”，先修复存储故障，再选择“重试删除”；等待期间仍占用额度，也不能下载或重命名。

未完成上传选择“取消并清理上传”，当前页面对应任务先暂停，再向服务器提交取消。清理失败显示“取消待重试”，完整预留继续保留，点击“重试取消清理”重试。初始暂存创建失败也会保留一个待取消清理任务。其他连接仍在写入时可能返回任务忙，请先暂停后重试。进程重启不自动清理已请求删除的记录，待重试状态与占用会保留。

只允许操作当前账号的文件和任务；管理员账号也不能代删、改名或读取别人的文件。本版不提供回收站。管理员维护入口可按期限清理未完成上传，后台策略默认关闭；全局预算与账号配额独立执行，详见存储维护说明。

### 2.2 发送给指定账号

在“文件工作台”选择自己的已完成文件，点击“发送给用户”。准确输入接收账号，先点击“核对接收账号”，核对返回的账号后勾选确认，再“确认发送”。不支持匿名或停用账号，也不能发送给自己。重复发送给同一接收者时复用有效授权，不产生第二份文件或重复计入存储。

接收者登录后进入“收发文件”的“收到的文件”，可下载或续传；没有原文件的重命名、删除和再次授权入口。下载沿用本机磁盘授权与完整性校验流程，进度和暂停操作会在收发页的传输队列显示。文件仍计入发送者存储，接收者只使用自己的下载带宽。

发送者在“收发文件”的“已发送的授权”中撤销。撤销会停止该授权后续下载与续传，原文件及其他接收者的授权保留。接收者可能已经保存或复制内容，撤销无法收回这些内容。撤销后重新发送是一条新授权，不会让原暂停任务自动恢复。

源文件开始删除或发送/接收任一账号被停用，相关授权立即失效；磁盘删除失败也不会恢复接收权限。重命名不影响授权和正确的续传位置。界面仅显示授权状态，不代表对方已读或已完整保存；双方可在安全中心查看投递、下载开始和撤销事件，无关普通账号不可查看。

本版每人最多 1000 条有效发送和接收授权，同一文件最多 32 个有效接收者；收发各按 12 条分页。核对/创建按账号每分钟合计最多 30 次，撤销最多 60 次。授权期限、外部免账号链接、群组、批量投递、通知以及后台归档不在本版范围。

### 2.3 存储与维护

管理员进入“存储与维护”，查看全局预算、磁盘余量、审计容量和本批过期任务，确认后清理或创建一致备份。普通账号没有维护入口，服务端另行鉴权。存储处于保护状态时，先排查磁盘和预留；刷新后重新取得状态，不能假定删除记录即已释放空间。备份成功显示已完成并校验，刷新后可核对编号、时间和大小；不提供网页内容下载，隔离恢复不覆盖已有目录。08 最小版已通过 B26～B29 及版本 6 容器验收；具体默认值、敏感资料保护、命令及限制见[存储维护与恢复](存储维护与恢复.md)，实际证据分界见[验证记录](验证记录.md)。

备份加密增强：新副本强制加密，初始化独立 `BACKUP_KEY_FILE` 后刷新维护页；缺钥时只拒绝备份、不回退明文。新列表区分旧明文/已加密并显示公开密钥编号。本地 39 项检查、139 场景和 Edge B36～B40 通过；66c22eb 真实 CI、最终镜像及版本 9 隔离容器通过，本机原卷升级也已保留 788 条原记录及账号/CA，并通过实际入口和新维护页补核。初始化、轮换、离线恢复和分别保管两类密钥见[备份加密与密钥管理](备份加密与密钥管理.md)。

## 3. 自动验证与报告

```powershell

npm run security:report
```

前者运行协议、账号聚合限速、浏览器会话竞争、部署验证器及真实 TLS/WSS 集成测试；后者独立启动隔离测试服务并输出：

- `reports/latest.html`：可直接打开阅读的报告。
- `reports/latest.json`：机器可读结果，管理员在“审计与验证”中刷新后可查看。

最小安全自动化另包含 `ci:workflow`、`ci:audit`、`ci:secrets`、`ci:scanner-test`、`ci:artifacts` 和 `ci:image`。检查策略、扫描器固定版本、公开结果及已知开发依赖的限时风险接受见[安全自动化](安全自动化.md)。远端 Actions 需使用者手动推送后取得实际结果；不自动部署或升级业务容器。当前生产依赖审计零告警，不能据此把未完成的镜像扫描或带限时例外的开发依赖审计写成零漏洞。

## 4. 审计日志独立校验

管理员可在界面导出日志及检查点。将检查点保存到服务器以外的位置，然后运行：

```powershell
npm run audit:verify -- 日志文件.json 独立检查点.json
```

校验工具检查序号、前驱摘要、当前摘要以及检查点是否匹配。修改日志副本后可重复验证；切勿为了演示修改真实运行数据库。没有独立可信检查点时，只能证明日志链内部一致，不能证明历史没有被整体重写。若攻击者同时控制日志、检查点与验证工具，当前方案不提供可信保证。

## 5. 本地容器部署

需要已正常启动的 Docker Desktop Linux 引擎；配置文件本身不能代替安装和启动容器引擎。

```powershell
docker compose config --quiet
docker compose up --build -d
docker compose ps
docker compose cp gateway:/data/caddy/pki/authorities/local/root.crt .local/container-ca.crt
```

由使用者核对并信任导出的 **容器本地 CA** 后，访问 https://localhost:8443。本地容器的 CA 与本机直接运行模式的 CA 不同。`docker compose exec app cat /data/accounts.json` 可在自己的终端查看容器随机账号，请勿将输出用于公开截图。

本机直接运行与容器部署会占用同一个 8443 端口，应先停止其中一个。停止服务使用 `docker compose down`；不要附加删除数据卷的参数，除非确定要销毁持久化数据。

容器部署设计：

- Caddy 网关只向本机映射 8443，使用自己的本地 CA；应用服务不映射宿主机端口。
- 应用进程 UID/GID 为 10001，根目录只读，只有数据卷及受限临时目录可写。
- 业务容器移除全部 Linux capabilities，并禁止提权；设置内存、CPU、进程数上限。
- 网关的 `/data` 与 `/config` 持久化保存其证书状态，网关也配置只读根目录与资源上限。
- 后端网络标为 internal；应用数据使用命名卷，报告目录只读挂载。网关同时连接 backend 和独立的 edge 入口网络，以便发布本机 HTTPS 端口；业务容器仅连接 backend。网关不能只连接完全隔离的 internal 网络，否则可能无法创建实际端口映射。参见 [Docker Compose 网络说明](https://docs.docker.com/compose/how-tos/networking/#internal-networks)。
- HTTPS/WSS 在网关终止，网关到同一宿主机的应用走隔离 Docker 内网 HTTP/WS。当前威胁模型信任容器宿主机，不声称容器内部这一跳也是 TLS。面对不可信容器网络时需增加后端 TLS/mTLS。
- 源码和凭据不会通过 Docker socket 暴露给应用。容器隔离不替代每次文件操作的用户授权。

## 6. 公网部署与 Let's Encrypt

提供独立的 `compose.public.yaml`，不会默认发布到公网。具备实际受控域名和服务器后，设置 `DOMAIN`、`ACME_EMAIL`，检查域名解析及 80/443 可达，再执行：

docker compose -f compose.public.yaml config --quiet
