# SafeDrop 安全验证矩阵

更新日期：2026-11-18。02、03、08、09、11 最小版已完成；11 基于 `f871afe`，自动、新增界面及实际版本 7 容器按各自范围通过。使用者已确认本矩阵纳入 **05 安全与协议回归、07 最终交付的 P0 内容**。后续安排以[开发路线图](开发路线图.md)为准；本轮只推进已授权的 11 及相关 05/06，不开始 04、17 或公网部署。

## 使用与判定

每行说明威胁、实际机制、测试入口和证据。状态只覆盖该行明确列出的断言，不代表相关攻击类别全部解决。本表是验证索引，不新增测试数量，也不是完整安全审计或标准认证。

当前自动证据为 **20 项检查及 131/131 安全报告**（原 109 加 MFA 22）。11 已通过严格 TLS/WSS 自动套件、编译版及 B30～B35 对应界面范围；实际版本 7 容器保留 539 条原记录，最终镜像内临时 MFA 检查、一致备份/隔离恢复通过，实际 HTTPS 页面显示安全卡片及 131/131。此前 `62bf323` 的版本 6 容器和 B01～B29 继续作为各轮历史证据。测试名称、运行时间、报告 SHA-256、容器/浏览器环境和范围见[验证记录](验证记录.md)及[浏览器验收清单](浏览器验收清单.md)。报告、截图和专用样本位于忽略提交的本地目录，不包含在源码交付中；可分享的证据需先排除账号资料、口令、令牌、私钥和真实用户内容。

## 每轮维护与最终交付

1. 开始模块时核对 Git 与实际机制，只调整该模块相关行及明确依赖；原有未验证项保持可见。
2. 完成后填写测试入口、实际断言、运行环境、提交基线和证据位置。自动、容器、浏览器的结果分别记录，不能相互替代。
3. 失败项保留问题和修复后的复验结果；计划中的功能只能在实现及相应验收完成后改为通过。
4. 07 报告及演示选取对应行，展示威胁输入、拒绝/恢复行为及结果核对，并交代信任宿主机、单进程部署等边界。
5. 可参考 [OWASP ASVS](https://asvs.owasp.org/) 选择适用要求，逐项记录适用性和验证情况；当前矩阵未完成逐条标准映射，不声明通过完整 ASVS 验证。
